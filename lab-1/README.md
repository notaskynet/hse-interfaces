## Шаг 2. Рассчитать скорость

Формула зависит от битов BRGH (`TXSTA<2>`) и BRG16 (`BAUDCON<3>`) в асинхронном режиме (SYNC = 0):

| BRG16 | BRGH | Формула            |
|-------|------|--------------------|
| 0     | 0    | Fosc / [64 (n + 1)] |
| 0     | 1    | Fosc / [16 (n + 1)] |
| 1     | 0    | Fosc / [16 (n + 1)] |
| 1     | 1    | Fosc / [4 (n + 1)]  |

- [ ] Выразить `n` из формулы для нужной скорости и округлить.
- [ ] Подставить округлённое `n` обратно и получить реальную скорость.
- [ ] Проверить, что отклонение от стандартной скорости меньше 5 %.

Пример для Fosc = 10 МГц (пересчитать, если кварц другой):

| Скорость | BRG16 | BRGH | n   | Реальная скорость | Отклонение |
|----------|-------|------|-----|-------------------|------------|
| 19200    | 0     | 1    | 32  | 18939,4           | −1,36 %    |
| 19200    | 1     | 1    | 129 | 19230,8           | +0,16 %    |
| 57600    | 0     | 1    | 10  | 56818,2           | −1,36 %    |
| 57600    | 1     | 1    | 42  | 58139,5           | +0,94 %    |

## Шаг 3. Прошивка, проект 1: символы и светодиоды

Библиотечными функциями пользоваться запрещено (`UART1_Init`, `UART1_Write` и т. п.) — только прямая работа с регистрами.

- [ ] Настроить порты:
  - порт A — цифровые входы (отключить АЦП через `ADCON1`, `TRISA = 0x3F`);
  - порт B — выходы (`TRISB = 0`);
  - RC6 — выход, RC7 — вход.
- [ ] Инициализировать UART:
  - `SPBRG` (и `SPBRGH`, если BRG16 = 1) — значение из шага 2;
  - `TXSTA`: TXEN = 1, SYNC = 0, TX9 = 0, BRGH по расчёту;
  - `RCSTA`: SPEN = 1, CREN = 1, RX9 = 0;
  - `BAUDCON`: BRG16 по расчёту.
- [ ] Передача: при нажатии кнопок RA0–RA5 отправлять символы `'0'`–`'5'`.
  - перед записью в `TXREG` ждать TXIF = 1;
  - отправлять один символ на одно нажатие (антидребезг, ожидание отпускания).
- [ ] Приём: принятый байт вывести на светодиоды RB0–RB7 (255 — горят все, 0 — не горит ни один).
- [ ] Для оценки выше 7 — приём по прерываниям:
  - разрешить RCIE (`PIE1<5>`), PEIE и GIE (`INTCON<6>`, `INTCON<7>`);
  - в обработчике проверять RCIF, читать `RCREG`, писать в `LATB`;
  - обрабатывать ошибку переполнения: при OERR = 1 сбросить и снова установить CREN.
- [ ] Проверить в USART Terminal (mikroC: Tools → USART Terminal, Ctrl+T).

### Устройство терминала

| Файл                                         | Что делает                                                              |
|----------------------------------------------|-------------------------------------------------------------------------|
| `dataformat.h`                               | интерфейс формата: байты → текст (`toText`), текст → байты (`fromText`) |
| `asciiformat.*`                              | формат ASCII                                                            |
| `numericformat.*`                            | байты числами через пробел; из него сделаны BIN и HEX                   |
| `formatregistry.*`                           | список форматов, из него заполняются оба выпадающих списка              |
| `datahistory.*`                              | история обмена: сырые байты с направлением (приём / передача)           |
| `historyview.*`                              | окно, показывающее одно направление истории в выбранном формате         |
| `mainwindow.*`                               | порт, раскладка окна, строка ввода                                      |

Данные хранятся один раз, в `DataHistory`, в виде байтов. Окна только отображают их, поэтому при смене формата перерисовываются целиком, а один и тот же формат работает и для вывода, и для ввода.

Как расширять:

- **Новый числовой формат** — одна строка в `FormatRegistry::createDefault()`, например DEC:
  ```cpp
  registry.add(std::make_unique<NumericFormat>("DEC", 10, 3, "", "49 255 10"));
  ```
  Он сразу появится и в «Отображении», и во «Вводе».
- **Формат с другой логикой** (например, текст с escape-последовательностями `\r\n`) — класс-наследник `DataFormat` с четырьмя методами, добавить в `terminal.pro` и зарегистрировать там же.
- **Ещё одно окно** (например, общий лог приёма и передачи) — ещё один `HistoryView` или свой подписчик на сигналы `DataHistory::appended` / `cleared`.

Без платы приложение можно проверить на виртуальной паре портов:

1. Запустить `socat -d -d pty,raw,echo=0 pty,raw,echo=0` — он напечатает два пути вида `/dev/ttys00N`.
2. В терминале вписать первый путь в поле «Порт» вручную (виртуальных портов в списке нет) и нажать «Открыть».
3. Во втором окне консоли читать отправленное (удобнее в HEX: `od -An -tx1 /dev/ttys00M`): `cat /dev/ttys00M`; отправлять в приложение: `printf 'hello\n' > /dev/ttys00M`.
